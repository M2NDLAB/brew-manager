# The 2.0.0 plan: D1–D11 and the user's precisions

- **Context**: after the scope change ([[2026-09-27-personal-terminal-tool]]) and the
  v1.5.0 release, a read-only assessment re-planned the work up to 2.0.0
  ([[sessions/2026-10-07-replan-v2-assessment]]: four analysts and a critic). The user
  approved the branches B1–B8 of [[plans/v2-personal-tool]] and the decisions D1–D11 as
  recommended, on 2026-10-07, with the precisions below.
- **Decisions (as recommended)**:
  - **D1 session recording**: keep `script(1)`, as corroboration of the summary (the log
    is a copy of the screen; only truthful module outcomes, B7, make the ✓ true). Drop
    the `_handle_log` prompt; compute `LOG_FILE` once in the parent, with a unique name;
    a per-run tmp dir created and removed by the parent. No `--no-log`, no automatic
    retention (≈2.5 MB a year; a manual one-liner in the README).
  - **D2** Ctrl+C exits 130 (an INT trap in the recorded child) instead of 2, which
    collided with "unknown module token". A contract change: docs/04, README, CHANGELOG,
    a pinned test.
  - **D3** module 10 (greedy) is RETIRED in 2.0.0; the number 10 stays reserved. Why:
    its detection never matched (it greps `auto_updates: true`, brew prints
    `(auto_updates)`; every recorded run found 0 casks), and since Homebrew 6.0 a plain
    `brew upgrade` (module 4) already upgrades an `auto_updates` cask whose app bundle is
    older than the tap version (verified on 6.0.21: opt-in since 5.1.6, the default since
    6.0.0). What `--greedy` still adds — re-syncing apps that updated themselves, and
    `version :latest` casks — is left to `brew upgrade --cask --greedy` by hand.
  - **D4** module 5's cleanup keeps its default `y` under `--yes`; its "LaunchAgents"
    justification is reworded in B3.
  - **D5** the removed names `bk`, `las`, `log`, `mas` exit 2 with a constant hint
    ("removed in 2.0.0 — see CHANGELOG.md"); they stay reserved forever.
  - **D6** no startup notice for leftover agents (none installed on this Mac); the
    removal procedure is documented.
  - **D7** brew's ask mode (6.0+): export `HOMEBREW_NO_ASK=1` (brew-manager owns
    consent), and module 0 shows the adopt plan (`--dry-run`, with
    `HOMEBREW_NO_AUTO_UPDATE=1`) before `_ask_danger`.
  - **D8** `--no-quit` on module 4's upgrades (and module 10's, while it exists).
  - **D9** Homebrew "6.0 or later, tested with 7.0.x" — README and the CLAUDE.md Stack
    line (B5).
  - **D10** the echo-on-data class (#3b) after 2.0.0, except module 0's three sites on
    the install path (B5).
  - **D11** the gate is PATH-BASED (IMP-030, applied in B1): one lens on the paths that
    delete, install, modify Homebrew's configuration or decide what runs; a refuter only
    where a change widens what such a path authorises; other edits verified by the
    author; no multi-hour workflows unless the risk justifies them.
- **The user's precisions (2026-10-07)**:
  - **B2 widens**: brew-manager must never leave Homebrew in developer mode.
    (1) Prevention: a test that fails if a Homebrew developer command appears in the
    code (the list taken from the installed brew or its documentation). (2) Detection:
    module 1 reads the developer-mode state READ-ONLY and reports it as a problem when
    on, whatever the cause. (3) Restore: when on, module 1 offers `brew developer off`
    and a return to the latest stable release (`brew update`), previewed under
    `--dry-run`, behind a confirmation, and done under `--yes` — a path that modifies
    the system, so a one-lens gate. The exact commands and their output are verified on
    the installed brew before use. The user tests it after the merge by running module 1
    on this Mac (in developer mode today); the manual commands are given as a fallback,
    with the expected outcome.
  - **D7/D8**: before use, verify on the installed brew that `HOMEBREW_NO_ASK` and
    `--no-quit` exist under those names and do what is needed; if a name differs or does
    not exist, STOP and propose the alternative.
  - **D3's claim** verified (above): true, with the "bundle older than the tap"
    precision.
  - **F10/F9** (one shared JSON per run) leave the post-2.0.0 list unless they have a
    concrete use for the personal tool: they were the Dashboard's foundation.
  - **A new CLAUDE.md rule** (IMP-031, applied in B1): brew-manager does not modify
    Homebrew's configuration except through an explicit action that is shown and
    confirmed.
- **Rule and contract edits approved with the plan**: CLAUDE.md (rule 8 and the
  sensitive-components paragraph — IMP-030; the Homebrew-configuration rule — IMP-031;
  the Stack line with Homebrew 6.0+; the `_module_14` note; the smoke rule; the runtime
  dependencies `mas`, `launchctl`, `open(1)`), docs/03, docs/00, docs/04 (names removed
  and reserved, the plist item deleted, exit 130, the exit codes of flag values, the
  "BM-18" clause), `.claude/commands/new-component.md`.
- **Discarded alternatives**: recording kept with its prompt fixed (a) or removed (c);
  module 10 fixed through JSON (it would revive an upgrade path that never ran); a
  startup notice for leftover agents; a gate on every edit to a sensitive file.
- **Consequences**: 2.0.0 is a MAJOR (module names removed, module 10 retired, exit 130,
  strict flag values, Homebrew 6.0+). The pre-Dashboard programme
  ([[plans/debt-cleanup-pre-dashboard]]) and roadmap-v2 are closed as superseded.
